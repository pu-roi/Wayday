## Implementation

The injectable NavigationDriver/TripNavigation boundary submits the remaining ordered targets plus final destination, preserves profile gates, merges adjacent identical targets and retains later return visits. It reserves the existing US$0.025 estimate for each submitted waypoint. Manual continuation reuses the established destination list without a new request. Actual in-flight route/advance/initialization operations survive caller deadlines and coalesce; stopped revisions cannot start guidance from a late response. Conservative dispatched-failure accounting, durable allocations and the US$0.782 disposable recovery floor are unchanged.

TripSession projects the next unfinished task, saves completion before revealing another task, and advances a native waypoint only after all tasks at that location are saved. Arrival only changes its presentation state. Save and advance failures preserve confirmed progress; late saved writes reconcile without silently advancing. Restart reconstructs remaining tasks from the existing accepted itinerary. There is no schema migration or persisted Google route geometry.

The native map mounts before route dispatch. Terms, phone location, map readiness, navigation location and route acquisition have distinct states. Map creation has a ten-second deadline, each location acquisition a thirty-second deadline and route acquisition a forty-five-second caller deadline. Caller timeout is not cancellation or a refund. The initial camera uses the current fix, followed by explicit top-down walking or tilted motorized guidance with SDK-managed zoom. GPS availability events preserve uncertainty without repeated recentering. User pan/recenter intent invalidates delayed overview actions. Whole trip fits every returned route segment and target; incomplete geometry fails visibly rather than drawing a fake road route.

Your trip retains native turn instructions, ETA/distance, compass, Recenter and attribution. A compact panel shows Mark this errand when done and a single checkbox/title. View plan and Navigation info are toolbar menu entries; the information sheet distinguishes navigation travel estimates from errands, appointments and business-hour feasibility. The final destination exposes Finish trip. Wayday's panel remains light, and native navigation uses automatic day/night mode. Supported TermsAndConditionsUIParams colors and existing Material Components Light.NoActionBar NormalTheme replace default dialog appearance without changing launch styles, terms content, links or acceptance storage. No provider, dependency, model, Cloud setting, billing allocation or background-navigation expansion occurs.

## Research basis

- [Google's Flutter Navigation plugin](https://github.com/googlemaps/flutter-navigation-sdk) and the locally pinned 0.11.2 implementation expose terms colors, camera following, GPS/arrival/route events, multi-destination continuation and route segments. Navigation forceNightMode controls active navigation colors; mapColorScheme does not.
- [Multi-destination guide](https://developers.google.com/maps/documentation/navigation/android-sdk/multi-destination) documents ordered waypoints and explicit continuation, with a 25-waypoint maximum.
- [Camera reference](https://developers.google.com/maps/documentation/navigation/android-sdk/camera) and [NavigationView reference](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/NavigationView) document the default overview's approximately 45-minute framing limit. D64 fits the returned complete remaining geometry instead.
- [Navigation controls](https://developers.google.com/maps/documentation/navigation/android-sdk/controls) and [policies](https://developers.google.com/maps/documentation/navigation/android-sdk/policies) support surrounding UI customization while preserving essential guidance, attribution and terms content.
- [Navigation billing](https://developers.google.com/maps/documentation/navigation/android-sdk/pricing) charges per submitted destination; camera operations and starting existing guidance do not justify another destination-list request. No remaining free balance is assumed.
