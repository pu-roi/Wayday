## Implementation

CurrentTripSection now appears below Today's date and above the editor. It shows the route icon, completed/assigned count and Resume trip, which opens the existing summary labelled Current trip. The bottom View saved plan shortcut and associated loading wording are replaced. Existing completed records remain recoverable until explicitly finished, because all errands done does not establish final-destination arrival. No automatic reusable entry or history feature is added.

FinishTripAction is shared by the summary and navigation's final-destination state after assigned errands are complete. Finish trip and clear Today? explains clearing all Today errands, locations and settings, including newer/left-out work, while preserving reusable trips, recurring lists and saved places. Cancel performs no cleanup. Back/View plan pauses guidance and retains progress. Confirmed cleanup returns a typed TripExit.finished result so a parent summary closes to Today; paused results keep its current progress. Completing tasks remains one errand at a time. The summary can finish an old completed trip without starting navigation or using Google services.

The itinerary repository separates deliberate initial save/acceptance from updateProgress, which requires a matching existing run and nondecreasing completed IDs. Finish verifies the stored run and completed assignments. Today and accepted-trip operations share a serial queue for their database. The empty Today write and matching trip deletion execute in one transaction; rollback retains both. The reset has empty errands/endpoints, current Manila date and existing default 8:30 AM departure, 6 PM finish and Motorcycle mode. Confirmed revision and a live revision guard reject changed Today; stale Today saves below the committed revision cannot restore cleared work. Repository and controller snapshots change only after commit. Memory implementations mirror these guards. No schema migration occurs; accepted v1/v2 and schema v7 remain readable.

The shared finishing controller coalesces repeated attempts, guards run identity and updates Today/recovery providers after success. The confirmation binds to the captured run and revision, requires renewed confirmation after edits and preserves explicit retry on storage failure. Today interactions are disabled while committing. No Cloud setting, dependency/provider, stored template, interpretation journal or request-accounting allocation is changed. Existing old trips are not purged during update.
