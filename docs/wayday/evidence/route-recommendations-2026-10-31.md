# D58 route-aware recommendation implementation and verification

Date: 2026-10-31, Asia/Manila. This records the owner-authorized implementation of the route-aware recommendation plan. It is a private Android pilot, not a live-provider or physical-phone qualification.

## Implemented behavior

Review errands now builds a proposal automatically. A native bridge over the pinned Places Android SDK requests actual display names, coordinates, locality/address components, business types and business status. It keeps this display content in memory. Search Along Route uses a Google Routes seed through the start, confirmed fixed points and destination. That seed is for discovery and does not impose an extra ordering rule. Each flexible need has at most one corridor request and two supplemental anchor requests, ten records per request, and a geographically varied shortlist. Round trips can use bounded anchors without a corridor. Identical work is coalesced and briefly reused in memory.

SDK and UI Kit references share Google identity while legacy serialization and expiring coordinate leases remain readable. Automatic candidates exclude invalid, foreign, unnamed, address-only and known-closed results. Confirmed street addresses can hydrate as fixed points without becoming automatic business recommendations. Explicit brands use the existing pinned Philippine NSI dictionary. Existing laundry/parcel pickups need their actual location. Fixed places offer manual correction, not another arbitrary business.

The existing on-device scheduler compares place combinations and stop order with asymmetric road times. The three-alternative/twelve-assignment bounds remain, as do mandatory timing, dependency rules, optional omissions, shared-stop task identity and existing visit estimates. Selected route legs are refined at their expected departure after service, waiting and buffers; feasibility is rechecked. Incoming leg distance/time and approximate matrix-based bypass comparisons remain distinct. No geographic distance is presented as road time. A five-minute, RAM-only matrix cache can project an unchanged subset; date/departure/profile/coordinate changes and backgrounding prevent reuse. Acceptance rejects changed or stale calculations.

Recommended places uses one Google map, numbered stops, monochrome category icons and synchronized rows. Rows show actual provider names, recognizable locality when supplied and a concise reason. Expansion shows detailed address, available category, uncertainty, calculation time and Change place. The map collapses for short/enlarged layouts and remains explicitly available. Traffic now is separate from scheduled traffic estimates. Alternatives preserve Previous/Next navigation, with a dedicated Search for a place action. Planning's manual picker combines saved places, standard UI Kit search and Choose on map on a Google map. It requires coordinates and omits Use name only. Other picker contexts retain name-only behavior. Current location remains an explicit foreground action with confirmation and approximate/denied/unavailable recovery.

Drift v6 adds only the source/context-bound recommendation_drafts singleton. It retains permitted selected references, personal labels, explicit overrides, approved/additional interpretation choices, endpoints and navigation position. Today, clarification sessions and accepted progress remain separate. Provider names/addresses, matrices and route geometry are absent from this row. Restart restores matching choices, hydrates the same Google IDs as necessary and recalculates roads without replacing a missing branch. Storage failures are visible. Closing during understanding cannot erase an existing draft; a late read cannot replace a newer start. Explicit start confirmation and Back/Close save through the draft path. Existing accepted itinerary v1/v2 readers remain intact.

## Request and data boundaries

The new SDK service shares the existing Google search ledger and pacing. Routes accounting remains independent and is checked before the bounded batch. These per-installation controls do not establish account-wide remaining free usage or spending limits. No Google quota, billing, account or credential restriction was changed. No Gemini cap was introduced; cache-first reuse, source validation and explicit failed/interrupted retry remain in force.

No ratings, reviews, opening-hours fields or Places routing summaries are requested by default. Business category establishes plausibility, not inventory, membership, hours or service availability. Google content stays on Google maps; coordinates are not sent to another provider for enrichment. Native Google map attribution and a visible Google Maps label remain. Third-party credit HTML retains safe HTTP(S) links/emphasis through the pinned Dart html parser, without executing HTML or scripts. The parser is MIT-licensed and locked with its csslib dependency.
